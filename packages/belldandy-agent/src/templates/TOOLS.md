# TOOLS.md - 本地工具说明

技能定义工具*如何*工作；这个文件记录*你这台机器*上的具体环境、通用工具调用规则、可复用 SOP 和真实踩坑记录。

---

## 一、这个文件该放什么

这个文件只保留三类内容：

1. **本地环境特有信息**：路径、SSH 别名、浏览器 / 扩展前置条件、当前服务限制。
2. **通用操作原则 / 可复用 SOP**：高频且值得反复执行的流程。
3. **真实踩坑记录**：参数坑、覆盖事故、环境限制、失败恢复经验。

不要在这里长期维护：

- 完整工具清单
- MCP / 技能 / 方法的数量统计
- 验证状态表
- 阶段性进度追踪

工具、技能、方法的能力摘要应优先通过运行时发现和按需检索完成，而不是在这里长期堆积。

## 二、P0 文件操作规范

### 2.1 强制动作

任何文件写、改、删、移动、重命名前，先输出一行：

`文件操作检查：路径=... 动作=... 已读原文=是/否 修改方式=局部修改/覆盖/追加/删除/移动/重命名 风险=低/中/高`

固定顺序：

`检索 -> 读取 -> 判断 -> 局部修改 -> 复读验证 -> 再继续下一步`

P0 硬规则：

- 修改已有文件前，必须先读取原文；禁止未读原文直接覆盖。
- 修改文件前，必须先复审文件类型（如 `md`、`json`、`yaml`、`toml`、`xml`、`doc`）；按文件类型决定内容格式与写法。
- 能局部改就不要整文件重写；优先 patch / 行级编辑。
- 不确定文件当前状态时，禁止直接 `overwrite`。
- 一次只做一个高风险文件动作，做完立刻复读验证。
- 删除、移动、重命名前，先确认目标路径、影响范围、回滚方式。
- 重要文件修改后，必须立即复读确认没有误清空、误覆盖、误追加。

### 2.2 `file_write` / 覆盖规则

- `path`：相对路径或允许范围内的绝对路径。
- `content`：**必须是字符串 String**，不能是对象或数组。
- `mode`：`overwrite` 或 `append`；默认 `overwrite`。

写入规则：

- 修改已有文件前，必须先 `file_read`。
- 先确认目标文件的类型与格式约束；例如 `json` 保持合法 JSON，`md` 保持 Markdown 结构，二进制 / 富文档格式不要按纯文本随意覆盖。
- 如无明确格式限制或用户要求，优先使用 Markdown 作为文档内容格式。
- 使用 `overwrite` 前，必须明确哪些旧内容要保留。
- 对提示词、记忆、配置、索引、说明文档这类重要文件，写前至少先读完整内容。
- 写入完成后，必须立刻复读目标文件。

### 2.3 `apply_patch` 使用规范

- 修改已有文件前，先读取原文并确认 patch 上下文真实存在。
- 对已有文件优先使用 `Update File`，不要误把现有文件当成 `Add File`。
- 如果 patch 上下文不匹配，不要硬补；先重新读取文件再生成 patch。
- 对重要文件优先小范围 patch，不做大块无验证覆盖。
- `Add File` 只用于新文件；如果目标已存在，必须改用 `Update File` 或 `file_write`。
- `apply_patch` 的输入必须是**原始补丁文本**；不要写成 `apply_patch(\`...\`)`、JSON 包装或代码块外壳，首行必须是 `*** Begin Patch`。
- 如果需要保留现有换行风格，改完后必须复读验证，确认没有破坏 `CRLF` / `LF`。

### 2.4 典型事故类型

| 错误类型 | 常见原因 | 教训 |
|----------|----------|------|
| `content` 类型错误 | 把对象传给 `file_write.content` | `content` 必须是字符串 |
| 覆盖错误 | 没有先读原文就 `overwrite` | 先读后写，避免永久丢失 |
| `apply_patch` 误用 | 对已有文件误用 `Add File` | 先确认是 `Update File` 还是 `Add File` |
| 文本替换事故 | 用命令行 `replace` / 正则粗暴改复杂 Markdown 或配置 | 复杂文件优先专用文件工具或小范围 patch |

### 2.5 正确用法示例

```javascript
// ✅ content 必须是字符串
file_write({
  path: "MEMORY.md",
  content: "# MEMORY\n\n- 记忆1\n- 记忆2"
})

// ✅ 修改前先读原文
const oldContent = file_read({ path: "MEMORY.md" })
const newContent = oldContent + "\n- 新增记忆"
file_write({ path: "MEMORY.md", content: newContent })
```

`apply_patch` 的 `input` 直接传下面这段 raw patch 文本，不要额外包一层函数调用、JSON 或代码块标记：

```patch
*** Begin Patch
*** Update File: MEMORY.md
@@
-# MEMORY
+# MEMORY
+
+- 新增记忆
*** End Patch
```

```javascript
// ❌ content 不能是对象
file_write({
  path: "MEMORY.md",
  content: { name: "易", age: 25 }
})

// ❌ 没读原文就覆盖高风险文件
file_write({
  path: "TOOLS.md",
  content: newContent,
  mode: "overwrite"
})
```

## 三、工具调用流程

### 3.1 文件修改 SOP

目标：把“能改”提升为“稳定改成”。

固定流程：

1. `rg` / 目录检索先定位目标文件与目标片段。
2. `file_read` 或等价读取先拿到当前原文，不凭旧记忆下手。
3. 判断动作类型：
   - 现有文件局部修改：优先 `apply_patch`
   - 新文件创建、整段重写、生成产物落盘：优先 `file_write`
4. 单次只做一个小补丁或一个明确写动作；不要把多文件大改塞进一次长 JSON。
5. 写完立刻复读目标文件。
6. 再看 diff / 关键片段是否符合预期。
7. 逻辑改动时补最小定向测试；至少做一次 smoke 验证。

关键决策规则：

- `apply_patch` 适合“小、准、可审查”的 diff，不适合把整文件改写伪装成 patch。
- `file_write` 适合新文件、整段覆盖、`replace` / `insert` / `append` 这类明确动作。
- 大改拆小做；每一步都复读，不赌下一步还能修回来。
- 如果工具调用 JSON 很长，优先拆小，否则容易被模型输出截断。

稳定成功的要点：

- 先读后改，避免上下文漂移。
- 不对已有文件误用 `Add File`。
- Patch 上下文必须真实且尽量唯一；重复片段多时不要偷懒。
- 高风险文件一次只做一个动作，做完立刻验证。
- Markdown / JSON / 配置文件分别按各自格式约束写，不混用文本策略。

### 3.2 浏览器 / 页面检查 SOP

1. 先判断目标是“看内容”还是“做交互”。
2. 只要涉及网页浏览、页面检查、DOM、Network、Console、表单、点击、等待或截图联动，优先使用浏览器自动化 / DevTools 路径。
3. 只有在“快速打开 / 轻量查看”且不需要调试能力时，才用轻量浏览路径。
4. 看图片、截图、本地图片内容时，不走浏览器路线，直接用图像理解工具。
5. 做完操作后，至少验证一次页面状态、控制台或目标元素结果。

### 3.3 图像理解 SOP

1. 先确认图片位于工作区或当前状态目录可访问范围内。
2. 优先使用内置 `image_understand`。
3. 必填参数是 `file_path`；可选参数包括 `prompt`、`focus_mode`、`focus_target`、`include_key_regions`、`max_key_regions`。
4. 用户上传图片优先用相对路径；工作区 / 状态目录内绝对路径也可用。
5. 失败时优先检查 `file_path`、访问范围、路径格式和模型配置，不要先怀疑图片内容本身。

### 3.4 时间 / 定时任务 SOP

1. 设置提醒或定时任务前先说明当前本地时间。
2. 明确用户说的是“本地时间”还是“UTC”。
3. cron / 定时任务显式写 `timezone`。
4. 如果时间表述含糊，先澄清再写任务。

## 四、参数坑点速查

| 场景 | 常见错误 | 正确做法 |
|------|----------|----------|
| `file_write` | `content` 传对象 / 数组 | `content` 必须是字符串 |
| `apply_patch` | 对已有文件误用 `Add File` | 已有文件用 `Update File` |
| `image_understand` | 沿用旧参数名 | 使用 `file_path` |
| 图片路径 | 默认写工作区外不可访问路径 | 优先工作区 / 状态目录内路径 |
| 定时任务 | 默认把 UTC 当本地时间 | 显式设置 `timezone` |

如果只是“记得大概参数”，不要直接赌；先重新读文档、方法或调用定义。

## 五、`image_understand` 使用示例

正确参数：

- `file_path`: 图片路径，必填
- `prompt`: 可选分析提示词
- `focus_mode`: 可选，`overview` / `detail_query`
- `focus_target`: 可选，细节查询时聚焦的对象 / 区域 / 文字
- `include_key_regions`: 可选，是否返回关键区域
- `max_key_regions`: 可选，关键区域最大数量

错误示例：

```javascript
// ❌ 沿用旧参数名
image_understand({
  image_source: "storage/attachments/xxx.jpg"
})

// ❌ file_path 为空
image_understand({
  file_path: ""
})
```

正确示例：

```javascript
image_understand({
  file_path: "storage/attachments/image_001.jpeg",
  prompt: "请详细描述这张图片的内容",
  focus_mode: "overview"
})

image_understand({
  file_path: "storage/attachments/image_001.jpeg",
  prompt: "请识别右上角状态标签的文字和颜色",
  focus_mode: "detail_query",
  focus_target: "右上角状态标签",
  include_key_regions: true
})
```
