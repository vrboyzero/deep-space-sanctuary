# ADR-0001：编码运行公共契约与领域状态边界

- 状态：已接受（阶段 0）
- 日期：2026-07-25
- 关联计划：[grok平台对比分析.md](grok平台对比分析.md) 第一里程碑阶段 0-1

## 背景

Star Sanctuary 已有 Conversation、Goal、Dynamic Workflow、Commander/Subtask 与 Plan Mode 等独立运行域。Headless CLI、后续 TUI、IDE adapter 与 SDK 需要同一套可演进的运行事件和控制语义，但不能为此复制任一领域的持久化状态机。

## 决策

### 1. 公共协议只做适配层

公共层使用 `CodingContextBinding`、`AgentRunEvent v1` 与 `RunControl v1` 关联既有运行。它不得创建或保存第二套 Conversation、Goal、Workflow Journal、Subtask、approval 或 `ConversationStore.planState`。

`CodingContextBinding.agentRunId` 是一次来源运行的公共引用；它不替代来源域的标识：

| 来源 | 必需引用 | 公共层权限 |
| --- | --- | --- |
| Conversation | `conversationId`、`agentRunId` | 发起新一轮、查看和取消既有 Conversation run。`continue` 始终是同一 Conversation 的新运行。 |
| Goal | `goalId`、可选 `nodeId`、`agentRunId` | 关联执行证据；不得将 coding run 成功写成 Goal 节点完成。 |
| Dynamic Workflow | `journalId`、可选 `workflowRunId`、`agentRunId` | 展示确定性工作流调用；不得把 Journal 当成会话或文件快照。 |
| Commander/Subtask | `taskId`、`agentRunId` | 关联受限 coder worker；不得越过 Commander 的派发、审查和 fan-in。 |
| Plan Mode | `conversationId` | 只读 bridge；不得按 coding run 自动新建或改写 `planState`。 |

### 2. 事件协议及兼容性

`AgentRunEvent v1` 固定包含 `version`、单调递增的 `seq`、`timestampMs`、`source`、`binding`、`type` 和对象形式的 `payload`。终态 `run.cancelled`、`run.interrupted`、`run.completed`、`run.failed` 之后不得再发出事件；迟到的来源回调被适配层忽略。

| 既有 Conversation 生命周期 | v1 事件 |
| --- | --- |
| 运行开始 | `run.started` |
| `agent.status` | `run.status` |
| `chat.delta` | `message.delta` |
| `tool_call` / `tool_result` | `tool.started` / `tool.completed` |
| `token.usage` | `run.usage` |
| `agent.budget_exhausted` | `run.budget_exhausted` |
| `chat.final` | `run.completed` |
| `conversation.run.stopped` | `run.cancelled` |
| `conversation.run.interrupted` | `run.interrupted` |
| 未捕获运行失败 | `run.failed` |

现有 Gateway 事件保持不变。阶段 1 仅以此 v1 视图输出 JSONL；不会重命名、删除或修改 WebChat 对现有事件的依赖。公共事件在发出前对 `apiKey`、`token`、`secret`、`password`、`authorization`、`cookie`、`session` 等字段脱敏。

### 3. 控制、权限与退出码

首批 `RunControl` 的意图是 `cancel`、`conversation.continue` 和绑定到指定 `agentRunId`、`toolCallId`、可选 `worktreeId` 的 `permission.respond`。非交互入口没有匹配范围内的授权时必须失败，不得默许或复用其他 worker 的批准。

CLI 保留稳定退出码：成功 `0`、输入错误 `2`、权限拒绝 `3`、运行失败 `4`、取消 `5`、输出 Schema 不合格 `6`、Gateway 不可用 `7`、中断 `8`。错误事件使用标准错误码；错误详情必须脱敏。

### 4. 恢复、checkpoint 与 worktree

三种恢复语义保持分离：

1. Goal resume 恢复治理与调度。
2. Workflow resume 按 `journalId` 和 fingerprint 重跑。
3. Conversation continue 在既有 transcript/context 中发起下一轮运行。

`WorkspaceRevisionCheckpoint` 仅用于后续文件级恢复，并以 `exact`、`managed_worktree`、`detect_only` 标明保证等级。它与 `GoalCheckpoint`、`WorkflowJournal` 分名、分存储、分状态机。

共享 worktree 的 owner policy 为：`user_session` 默认保留且 dirty/untracked 时拒绝普通删除；`workflow_call` 仅在 artifact 完整且保留策略允许时清理；`subtask` 的强制清理仅限既有受管后台目录。阶段 0 不创建 worktree，也不提供删除、apply 或 rewind 操作。

### 5. 传输与配置决策

v1 是宿主无关的内存/JSON 对象契约。阶段 1 以 JSONL 消费它，stderr 承载诊断；TUI、IDE adapter 和 SDK 以后续阶段通过同一契约接入。ACP 不是阶段 0 的正式兼容面，必须先经目标编辑器互操作验证。

阶段 0 不新增环境变量、发行模板或配置审计项：协议版本、事件顺序、脱敏字段和退出码属于安全与兼容性契约，允许运行时切换会导致同一客户端得到不一致语义。阶段 1 若新增可调的时间、轮次、token、费用或工具限制，必须按全阶段工程约束提供安全默认值、环境变量、模板和配置审计，非法或缺失值回退默认。

## 结果与回滚

新增模块位于 `packages/belldandy-core/src/coding-run/`，没有调用 Conversation Store、Goal Manager、Workflow Runtime、Task Runtime 或 Plan Store 的写接口。当前 v1 仅作为内部公共契约；未来出现不兼容需求时新增版本，不原地改变 v1 的字段或事件终态规则。回滚阶段 0 只需停止使用该适配层，不影响现有 Gateway/WebChat 生命周期事件。
