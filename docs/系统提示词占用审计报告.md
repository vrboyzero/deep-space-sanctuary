## 6. 主要膨胀来源

### 6.1 `TOOLS.md`

这是当前最大的单个 workspace 文档来源。

从真实 blob 里能看到它包含大量分级工具目录与运行说明，例如：

- 文件与工作区
- 浏览器与视觉
- Chrome DevTools MCP
- Goal 系统
- Canvas
- 子代理与委派
- 技能系统
- Context7
- 经验系统
- 多媒体输出
- 工具优先级、教训记录、时间规范等

问题不在于内容没价值，而在于：

- 这部分是“长期完整工具手册”
- 不是“每轮都必须出现在 system prompt 的最小执行集”

### 6.2 `MEMORY.md`

当前 `MEMORY.md` 体积也已经很大，并且包含大量长期项目背景与人物/关系/设定型内容。

- `MEMORY.md` 当前更像“长期知识总册”

### 6.3 `SOUL.md` 与 `AGENTS.md`

## 8. 风险判断

### 风险级别

`中高`

### 主要风险

1. 主 system prompt 过长，压缩了用户消息与工具返回的上下文预算。
2. 规则与背景文档高度耦合，导致每轮推理负担偏重。
3. 方法/技能资产继续增长后，`dynamic-runtime` 会持续上升。
4. 静态注入中存在“长期手册型内容”，而不是“当前任务最低必要内容”。

### 当前最明显的大头

1. `TOOLS.md`
2. `MEMORY.md`
3. `SOUL.md`
4. `AGENTS.md`
5. `dynamic-runtime` 治理规则块

## 9. 优先收缩建议

### 方案 A：先控静态大头

优先级最高，建议先做。

1. 缩 `TOOLS.md`
2. 缩 `MEMORY.md`
3. 评估 `SOUL.md` / `AGENTS.md` 中可下沉到 methods 的 SOP 内容

建议做法：

- `TOOLS.md` 只保留“路由原则 + 工具分层 + 少量关键坑位”
- 把长工具目录、测试记录、历史经验移到 methods 或 docs
- `MEMORY.md` 只保留真正长期稳定、每轮都高价值的记忆

### 方案 B：控 runtime 治理块

优先级第二。

重点目标：

- Tool Behavior Contracts 压缩
- Team/Delegation/Governance 规则压缩
- Method / Skill Summary 缩短

建议做法：

- 把一部分通用治理规则收敛成更短的摘要版
- 对 Method / Skill Summary 只保留计数 + Top N 推荐，不列太多条目

### 方案 C：显式设置 system prompt 上限

优先级第三。

设置：

- `BELLDANDY_MAX_SYSTEM_PROMPT_CHARS`

当前代码已经支持超长后从低优先级 section 开始裁剪，见 [system-prompt.ts](/E:/project/star-sanctuary/packages/belldandy-agent/src/system-prompt.ts:661)。

建议：

- 不要继续保持 `0 / 不限制`
- 可以先试一个保守上限，再观察被裁剪 section

### 方案 D：方法/技能摘要改为“更强按需”

优先级第四。

如果后续 methods / skills 继续增长，建议把：

- “全量摘要注入”

改成：

- “仅注入计数 + 推荐项 + 搜索提示”

否则这块会随着资产增长持续膨胀。

## 10. 建议的治理顺序

建议按这个顺序推进：

1. 先审 `TOOLS.md`
2. 再审 `MEMORY.md`
3. 再收 `dynamic-runtime` 规则块
4. 最后再决定是否调低 `BELLDANDY_INJECT_METHOD_SKILL_LIST`
5. 然后设定 `BELLDANDY_MAX_SYSTEM_PROMPT_CHARS`

原因：

- 前两项收益最大
- 且不会直接破坏核心运行机制
- runtime 治理块压缩需要更谨慎，避免误伤行为约束

## 11. 审计结论

当前主 Agent 的系统提示词占用已经进入“需要主动治理”的阶段。

根因不是单个 bug，也不是某一条额外说明，而是：

- `TOOLS.md + MEMORY.md + SOUL.md + AGENTS.md` 这几份长文档本体
- 再叠加一整套 runtime 治理规则
- 再叠加 methods / skills 摘要索引

如果不收口，随着 methods、skills、记忆和工具治理继续增长，主 system prompt 还会继续膨胀。
