游戏策划案 AI 撰写助手需求说明

一、需求背景

当前游戏策划案撰写过程中，常见问题包括：

1. 不同策划写作结构不统一，评审成本高。
2. AI 直接生成的策划案容易“看起来完整”，但实际缺少流程、配置、边界、埋点、风控等关键落地内容。
3. 多轮讨论后，方案容易偏离最初设计目的。
4. 策划案缺少版本记录、变更说明和待确认事项，后续协作容易混乱。
5. 美术、程序、数据、测试所需信息经常分散在正文中，无法直接拆解执行。

因此，需要一个专门面向游戏策划案撰写的 AI 助手，帮助策划人员按照统一标准完成策划案生成、补全、审查和迭代。

二、产品定位

该工具不是普通文档写作助手，而是一个游戏策划案标准化撰写与审查助手。

核心目标不是“帮用户快速写一篇文档”，而是：

帮助游戏策划将初步想法、零散需求或已有方案，整理成结构完整、逻辑清晰、可评审、可开发、可追踪的正式策划案。

AI 在其中承担三个角色：

1. 策划案撰写者：根据用户输入生成规范文档。
2. 主策划审查者：主动检查设计目的、用户路径、经济风险、边界条件等问题。
3. 协作信息整理者：提炼程序、美术、数据、测试所需的执行清单。

三、目标用户

主要用户：

1. 游戏产品策划
2. 系统策划
3. 活动策划
4. 数值策划
5. 运营策划

协作对象：

1. 主策划
2. 制作人
3. 程序
4. 美术
5. 测试
6. 数据分析
7. 运营

四、核心使用流程

AI 撰写策划案时，必须按照以下流程执行。

4.1 输入需求

用户可以输入：

1. 一句话功能想法
2. 初版策划草稿
3. 会议纪要
4. 竞品参考
5. 活动规则
6. 配置表草稿
7. 历史方案
8. 截图或界面描述

AI 需要先识别用户输入属于哪类需求：

1. 新功能策划案
2. 旧方案优化
3. 活动方案撰写
4. 系统规则补全
5. 配置表整理
6. 埋点需求整理
7. 美术需求拆解
8. 方案评审检查

4.2 需求拆解

AI 不应直接生成完整正文，而应先拆解需求。

拆解维度包括：

1. 功能目标
2. 目标用户
3. 使用场景
4. 用户入口
5. 核心流程
6. 奖励或权益
7. 配置需求
8. 界面需求
9. 渠道差异
10. 版本兼容
11. 风控风险
12. 数据埋点
13. 待确认问题

如果关键信息缺失，AI 应主动标记为“待确认”，不能自行编造。

4.3 生成大纲

AI 需要先输出策划案大纲，让用户确认。

大纲必须包含：

1. 文档信息
2. 版本记录
3. 功能背景
4. 设计目标
5. 目标用户
6. 功能流程
7. 详细规则
8. 界面与交互
9. 配置表
10. 美术资源需求
11. 数据埋点需求
12. 边界条件
13. 渠道差异与版本兼容
14. 风控设计
15. 待确认事项

建议将“大纲确认”设为强制流程：未确认大纲前，不进入完整正文生成。因为策划案最大的问题通常不是文笔，而是结构和方向错误。

4.4 生成策划案正文

用户确认大纲后，AI 按标准结构生成完整策划案。

正文要求：

1. 使用清晰层级，如 1、1.1、1.1.1。
2. 每个功能模块必须说明设计目的。
3. 每个核心流程必须包含触发条件、用户操作、系统反馈、结束状态。
4. 所有配置项必须整理成表格。
5. 所有待确认内容必须显式标记。
6. 所有涉及奖励、货币、实物、付费的内容必须补充风控说明。
7. 所有涉及不同平台或渠道的内容必须说明差异。

五、标准输出内容

一份完整策划案至少应包含以下内容。

5.1 文档基础信息

包括：

1. 文档名称
2. 所属项目
3. 功能模块
4. 当前版本
5. 创建人
6. 更新人
7. 更新时间
8. 文档状态

文档状态建议：

草稿中 → 待评审 → 评审修改中 → 待开发 → 开发中 → 已上线 → 已归档 → 已废弃

5.2 版本变更记录

每次修改必须记录：

1. 版本号
2. 修改时间
3. 修改人
4. 修改内容
5. 修改原因
6. 影响范围

5.3 功能目标

每个功能必须绑定至少一个目标：

1. 留存
2. 收入
3. 活跃
4. 体验
5. 转化
6. 回流
7. 消耗
8. 社交

同时需要说明：

1. 目标用户是谁
2. 预期影响是什么
3. 与现有系统有什么关系
4. 是否有量化目标

5.4 功能流程

必须覆盖完整用户路径：

入口 → 触发条件 → 用户操作 → 系统反馈 → 奖励/结果 → 退出/结束

如果存在多条件分支，需要用表格或判断树说明。

5.5 界面与交互

AI 需要输出：

1. 页面列表
2. 核心信息层级
3. 按钮行为
4. 状态反馈
5. 弹窗规则
6. 文本原型图

弹窗必须说明：

1. 弹出时机
2. 弹出频率
3. 弹窗优先级
4. 关闭方式
5. 是否支持不再提醒
6. 按钮跳转目标
7. 异常处理方式

5.6 配置表

所有可配置项必须整理成配置表。

字段包括：

1. 字段名
2. 字段类型
3. 是否必填
4. 控制端：前端 / 服务端 / 中台
5. 字段说明
6. 示例值
7. 计算公式或来源

5.7 美术资源清单

如果方案涉及界面、图标、动效、奖励展示，需要输出美术清单。

字段包括：

1. 资源名称
2. 使用位置
3. 资源类型
4. 尺寸规格
5. 动效要求
6. 优先级
7. 备注

5.8 数据埋点与查询清单

每个功能必须补充数据需求。

至少包括：

1. 曝光事件
2. 点击事件
3. 核心操作事件
4. 转化漏斗事件
5. 异常行为事件

埋点字段包括：

1. 事件名
2. 触发条件
3. 上报参数
4. 统计维度
5. 查询用途

5.9 边界条件

必须覆盖：

1. 网络异常
2. 数据异常
3. 重复点击
4. 快速切换
5. 强制退出
6. 跨天 / 跨周 / 活动结束
7. 多设备登录
8. 并发操作

每个异常场景都要说明：

1. 用户侧表现
2. 系统侧处理

5.10 渠道差异与版本兼容

如果涉及多渠道或多平台，必须说明：

1. APP 是否支持
2. 小游戏是否支持
3. 有实物渠道是否支持
4. 无实物渠道是否支持
5. 老版本用户是否可见
6. 是否需要强制更新
7. 老版本数据如何处理

5.11 风控设计

涉及以下内容时必须触发风控审查：

1. 虚拟货币
2. 实物奖励
3. 兑换券
4. 多乐币
5. 付费权益
6. 抽奖
7. 排行榜
8. 邀请裂变
9. 回流奖励

风控需要说明：

1. 可能被薅羊毛的路径
2. 工作室批量操作风险
3. 异常行为识别方式
4. 发奖限制
5. 权益回收规则
6. 退款处理规则

5.12 待确认事项

所有不确定内容必须汇总到文档末尾。

字段包括：

1. 序号
2. 待确认内容
3. 影响范围
4. 负责人
5. 当前状态

六、AI 讨论与审查规则

在用户与 AI 讨论方案时，AI 不能只顺着用户写，必须主动审查。

6.1 目的校验

AI 必须判断每个设计是否服务核心目标。

示例：

1. 如果目标是提升功能曝光，就不应该默认隐藏入口。
2. 如果目标是提升留存，就不应该只设计一次性奖励。
3. 如果目标是提升付费，就必须明确付费转化路径和权益价值。

6.2 玩家行为审视

每个涉及玩家操作的设计，AI 必须检查：

1. 玩家会不会用
   路径是否过长，入口是否明显，操作是否符合习惯。

2. 玩家为什么用
   驱动力是奖励、成长、社交、炫耀、好奇，还是任务压力。

3. 玩家用了之后会怎样
   是否有正反馈，是否形成循环，是否会一次性体验后遗忘。

6.3 强观点输出

AI 不能只列方案，必须给出推荐结论。

输出方式应类似：

我建议采用方案 A，因为它更符合提升留存的目标，并且对现有经济系统冲击更小。
不建议采用方案 B，因为它虽然短期点击率更高，但会提高薅羊毛风险。

6.4 确认前检查

当用户说“可以了”“就这样”“更新文档”时，AI 必须先检查：

1. 默认行为是否符合设计目标
2. 是否存在鸡生蛋困境
3. 反馈闭环是否完整
4. 是否遗漏用户状态
5. 是否存在渠道差异
6. 是否存在经济或风控风险

检查通过后，才能进入正式更新。

七、标准化与归档需求

AI 生成文档时，需要支持标准化命名。

命名格式建议：

[游戏名]_[功能模块]_[文档类型]_[版本号]_[YYYYMMDD]

示例：

宠物大冒险_回流签到_功能策划案_V1.0_20260606

Git 提交说明建议：

docs: update 回流签到功能策划案 v1.0

每次文档更新需要说明：

1. 本次新增内容
2. 本次修改内容
3. 本次删除内容
4. 对程序 / 美术 / 数据 / 测试的影响
5. 是否存在待确认风险

八、长期记忆需求

AI 需要支持项目长期记忆，用于后续写策划案时复用上下文。

长期记忆包括：

1. 项目基础信息
2. 游戏核心玩法
3. 货币体系
4. 奖励体系
5. 会员体系
6. 签到体系
7. 活动体系
8. 渠道差异规则
9. 文档模板规范
10. 埋点命名规范
11. 历史方案
12. 已废弃方案
13. 历史评审结论

长期记忆必须支持：

1. 启用
2. 停用
3. 编辑
4. 过期标记

原因：如果长期记忆无法管理，AI 容易引用旧规则，导致新方案被历史错误污染。

九、需求优先级

9.1 P0：必须实现

1. 标准策划案结构生成
2. 大纲确认后再生成正文
3. 配置表生成
4. 流程拆解
5. 边界条件检查
6. 待确认事项汇总
7. 目的校验
8. 玩家行为审视

9.2 P1：重要功能

1. 美术资源清单
2. 数据埋点清单
3. 渠道差异说明
4. 版本变更记录
5. 风控检查
6. 文档命名规范
7. Git 提交说明生成

9.3 P2：增强功能

1. 长期记忆
2. 历史方案检索
3. 多模板管理
4. 多项目归类
5. 自动审查评分
6. 多人协作状态流转

十、最小可用版本建议

MVP 不建议一开始做复杂文档编辑器。最小版本应该先解决“AI 写出来的策划案是否规范”。

MVP 应包含：

1. 用户输入功能想法或草稿
2. AI 拆解需求
3. AI 生成大纲
4. 用户确认大纲
5. AI 生成完整策划案
6. AI 输出缺失项和待确认事项
7. AI 生成配置表、埋点清单、美术清单

这个版本先保证策划案质量，再考虑在线编辑、协作流转、Git 集成和长期记忆。

十一、一句话总结

做一个面向游戏策划的 AI 策划案撰写助手，让 AI 按固定流程先拆解需求、确认大纲，再生成包含流程、原型、配置表、美术清单、数据埋点、边界条件、渠道差异、风控检查和版本记录的标准化策划案，并在多轮讨论中持续审查设计目的、玩家行为和落地风险。
