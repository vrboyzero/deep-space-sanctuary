# Star Sanctuary 开发使用说明（CLI / TUI / 无头与桥接）

> 适用版本：0.5.4 起，含 2026-09-08「开发能力精进」收尾后的 CLI / TUI / 桥接能力。
>
> 本文面向**在本仓库做开发、调试、自动化与集成**的使用者，重点回答三件事：
> 1. 以前只能通过 WebChat 对话，现在在终端里怎么用？
> 2. CLI / TUI / 无头运行分别适合什么场景？
> 3. 怎么把 Star Sanctuary 的开发运行时接到别的 Agent、IDE 或 CI 上？
>
> 相关文档索引见文末第 13 节。

---

## 0. 三条使用路径：先选一条

| 路径 | 入口 | 适合谁 / 什么时候用 | 关键特点 |
|---|---|---|---|
| **WebChat（原有）** | 浏览器打开 `http://127.0.0.1:28889` | 日常聊天、轻量问答、语音、看板式治理 | 图形界面、配对保护、功能最全但需要鼠标操作 |
| **CLI 交互式（新增）** | `bdd tui` | 在终端里做开发：改代码、看 diff、管会话、看运行态 | 四个标签页、权限弹窗、变更检查点、受控推送 |
| **CLI 无头 / 桥接（新增）** | `bdd agent run`、`bdd coding-run stdio`、`bdd coding-run mcp` | 脚本化、CI、被别的 Agent/IDE 调用 | 机器可读事件、预算与权限护栏、NDJSON / MCP 协议 |

> 一句话：**WebChat 是"陪聊 + 治理面板"，CLI 是"开发工作台"，无头与桥接是"给别人调用的接口"**。三者共用同一个 Gateway、同一套安全边界、同一份状态目录。

## 1. 环境准备

### 1.1 前置条件

- Node.js ≥ 22.12.0（推荐 22 LTS）
- `corepack pnpm`（仓库使用 pnpm 10.x）
- Windows 下命令请在 **PowerShell** 中执行；WSL 内请用对应 Linux 命令

```powershell
# 安装依赖
corepack pnpm install

# 生成版本信息 + 构建 Web 资源 + 全量构建（首次或改动包结构后）
corepack pnpm build
```

### 1.2 配置（三种方式任选）

| 方式 | 命令 / 路径 | 说明 |
|---|---|---|
| 向导（推荐首次） | `corepack pnpm bdd setup` | 交互式填写 base URL、API Key、鉴权模式 |
| 命令行读写 | `bdd config list` / `get <KEY>` / `set <KEY> <VALUE>` / `edit` / `path` | 直接管理状态目录下的 `.env.local`，`list` 默认遮蔽敏感值（`--show-secrets` 才显示） |
| 手工编辑 | 状态目录的 `.env.local`（例如 `H:\.star_sanctuary\.env.local`） | 高级配置、批量调整时最方便 |

状态目录由 `BELLDANDY_STATE_DIR` 决定（未设置时默认 `~/.star_sanctuary`）。仓库内还提供两份模板：

- `.env.example`：**全量参考**，每个变量都有中文说明与默认值（含本轮新增项）；
- `packages/star-sanctuary-distribution/src/templates/default-env/runtime.env.local`：**发行模板**，新用户开箱即用的成熟档（敏感值已清空为 `""`）。

### 1.3 自检与启动

```powershell
corepack pnpm bdd doctor                 # 环境与配置体检
corepack pnpm bdd doctor --check-model   # 额外发一次最小模型请求，验证连通性

corepack pnpm bdd start                  # 前台启动 Gateway
corepack pnpm bdd start -d               # 后台（daemon）启动
corepack pnpm bdd status                 # 查看 daemon 状态
corepack pnpm bdd stop                   # 停止 daemon

corepack pnpm bdd dev                    # 开发模式（带 supervisor，配合 dist guard）
```

> ⚠️ **`bdd tui` 与 `bdd agent run` 都通过本地 Gateway RPC 工作，因此需要 Gateway 已在运行**。先 `bdd start`（或 `bdd dev`），再开另一个终端跑 TUI。

## 2. CLI 命令总览

`bdd`（等价于 `belldandy`）来自 `@belldandy/core`；仓库内统一用 `corepack pnpm bdd <命令>`。

### 2.1 运行与生命周期

| 命令 | 作用 |
|---|---|
| `bdd start [-d]` | 前台 / 后台启动 Gateway |
| `bdd stop` / `bdd status` | 停止 / 查看 daemon |
| `bdd dev` | 开发模式启动（带 dist 防护，改源码自动重建） |
| `bdd doctor [--check-model]` | 体检；`--check-model` 会真实发一次最小请求 |
| `bdd console [--json] [--watch] [--interval <秒>]` | 轻量终端运行态控制台（可持续刷新 / JSON 输出） |

### 2.2 开发工作台

| 命令 | 作用 |
|---|---|
| `bdd tui [--cwd <目录>]` | 打开交互式开发工作台（见第 3 节） |

### 2.3 无头开发（脚本化）

| 命令 | 作用 |
|---|---|
| `bdd agent run` | 跑一次完整对话 Agent 任务（可输出 JSONL 事件） |
| `bdd agent continue` | 在已有会话上继续新一轮 |
| `bdd agent status` / `inspect` | 查看某个 run / 会话元数据、cwd 项目规则 |
| `bdd agent steer` / `steer-status` | 在下一个模型边界"改口"（注入新指令） |
| `bdd agent follow-up` / `follow-up-status` | 排队追加输入 |
| `bdd agent replace` / `cancel` | 替换 / 取消正在运行的 run |
| `bdd agent task-projections` | 以 JSON 读取受限的任务投影集合 |

### 2.4 桥接与集成

| 命令 | 作用 |
|---|---|
| `bdd coding-run mcp` | 把开发运行时暴露为 **MCP stdio server**（供 Claude Code / Codex / IDE 调用） |
| `bdd coding-run stdio` | **NDJSON** 逐行协议桥（自研客户端、脚本、CI 用） |

### 2.5 会话取证与排障

| 命令 | 作用 |
|---|---|
| `bdd conversation list` | 列出可导出的持久化会话 |
| `bdd conversation timeline` | 把会话投影成可读时间线 |
| `bdd conversation export` | 导出会话 transcript 包 |
| `bdd conversation prompt-snapshot` | 导出某次 run 的 prompt 快照（排查"模型到底看到了什么"） |
| `bdd conversation exports` | 列出最近写盘的导出文件 |

### 2.6 配置、接入与扩展

| 命令 | 作用 |
|---|---|
| `bdd setup` / `bdd config ...` | 配置向导 / 配置读写 |
| `bdd configure bridge|community|models|webhook|cron` | 高级模块配置（桥接目标、社区、备用模型、Webhook、定时任务） |
| `bdd pairing approve|revoke|list|pending|cleanup|export|import` | 客户端配对管理 |
| `bdd relay start` / `bdd relay credential` | 浏览器 CDP 中继服务 / 打印扩展配对凭据 |
| `bdd marketplace list|install|enable|disable|update|uninstall|audit` | 插件市场安装与信任审计 |
| `bdd community` | 配置 office.goddess.ai 社区连接 |

## 3. 交互式开发工作台：`bdd tui`

```powershell
corepack pnpm bdd start          # 先启动 Gateway（另一个终端窗口）
corepack pnpm bdd tui --cwd E:\project\star-sanctuary
```

**前提**：终端必须是交互式 TTY（stdin/stdout 都是 TTY）；否则会提示 `bdd tui requires an interactive stdin and stdout.`

### 3.1 四个标签页

| 标签页 | 内容 |
|---|---|
| **chat** | 与 Agent 对话：流式回复、工具调用摘要、权限请求弹窗 |
| **sessions** | 持久化会话列表，可切换/继续历史会话 |
| **changes** | 变更工作区：**Worktrees**（托管/启动目标、cwd、ready/blocked/unavailable）与 **Revision Checkpoints**（tracked / untracked / conflict 变更、变更路径、逐 hunk 导航） |
| **runtime** | 运行态：Gateway 连接与配对状态、体检 pass/warn/fail 计数、agents / subtasks 统计、命令作业列表 |

### 3.2 键位

| 按键 | 作用 |
|---|---|
| `Tab` / `Shift+Tab` | 切换标签页 |
| `←` / `→` | 切换标签页；在 changes 标签内切换 Worktrees ↔ Revision Checkpoints 焦点 |
| `Enter` | chat：发送；sessions：选中会话；changes：选择工作区 / 预览某次检查点；runtime：刷新 |
| `PageUp` / `PageDown` | changes：逐页查看变更；runtime：翻看命令作业 |
| `Backspace` / `Delete` | runtime 标签内：请求取消命令作业 |
| **`Ctrl+P`** | changes 标签内：发起**受控远端交付推送**（需 `BELLDANDY_REMOTE_DELIVERY_TARGETS_JSON` allowlist） |
| `Ctrl+C` | 取消当前动作；空闲时退出 |

### 3.3 权限弹窗

Agent 调用高风险工具时会弹出权限请求：

| 按键 | 作用 |
|---|---|
| `↑` / `↓` | 在多个待决权限请求之间移动 |
| `Tab` / `←` / `→` | 在选项间切换（允许 / 拒绝） |
| `Enter` | 确认当前选项 |
| `Esc` | 暂时关闭弹窗（请求仍保留在队列里） |

### 3.4 一次典型开发流程

1. `chat` 里描述任务（例：*"修复 packages/belldandy-agent 里的 XX 缺陷，并补测试"*）；
2. 观察工具调用摘要，遇到权限弹窗时按需放行；
3. 切到 `changes` 看具体改了哪些文件 / 哪些 hunk，需要时预览检查点；
4. 切到 `runtime` 确认 Gateway 健康、子任务与命令作业状态；
5. 满意后按 `Ctrl+P` 走受控推送，或先切到 `sessions` 保存/继续这个会话。

## 4. 无头开发运行：`bdd agent run`

### 4.1 最小示例

```powershell
corepack pnpm bdd agent run `
  --prompt "把 packages/belldandy-skills/src/builtin/fetch.ts 里的超时改成可配置，并补单测" `
  --cwd E:\project\star-sanctuary `
  --permission-mode accept-edits `
  --max-turns 12 --max-cost-usd 0.5
```

从标准输入喂 prompt（省略 `--prompt` 时读 stdin），加 `--jsonl` 输出机器可读事件流：

```powershell
"解释 packages/belldandy-core/src/server.ts 的请求分发" | corepack pnpm bdd agent run --jsonl --cwd .
```

### 4.2 参数分组

| 分组 | 参数 | 说明 |
|---|---|---|
| 身份 / 范围 | `--state-dir`、`--cwd`、`--conversation-id`、`--agent-id`、`--model-id`、`--workspace-snapshot-root` | 状态目录、文件工具作用域、续跑哪条会话、用哪个 Agent/模型 |
| 期望校验 | `--expected-resolved-model-id` | 实际解析出的模型不是指定值就失败（防止悄悄换模型） |
| 权限与工具 | `--permission-mode`（`plan` / `accept-edits` / `confirm`）、`--tool-allow`、`--tool-deny`（deny 优先） | 只读分析用 `plan`；受控改动用 `accept-edits` |
| 预算护栏 | `--max-turns`、`--max-tokens`、`--max-cost-usd`、`--max-tool-calls`、`--model-loop-budget-policy cost-containment-v1` | 超限即停；`--max-cost-usd` 依赖模型定价配置（见第 9 节） |
| 能力门 | `--require-capability`、`--require-tool`、`--require-mcp-server`、`--require-plugin`、`--require-skill` | 缺一项即失败（"环境不具备就别跑"） |
| 结果契约 | `--require-workspace-mutation`、`--required-changed-paths`、`--required-residual-identifiers`、`--output-schema` | 没真正改到指定文件 / 还残留旧标识符 / 最终输出不符 schema，都判失败 |
| 自动化档 | `--automation-profile bare` | 确定性自动化模式（跳过部分运行时增强） |
| 超时 | `--timeout <毫秒>` | 单次运行上限 |

### 4.3 退出码

| 码 | 含义 |
|---|---|
| `0` | 成功 |
| `2` | 输入非法 |
| `3` | 权限被拒 |
| `4` | 执行失败 |
| `5` | 被取消 |
| `6` | 输出不符合 `--output-schema` |
| `7` | Gateway 不可用 |
| `8` | 被中断 |

### 4.4 长任务协同

```powershell
# 看某个 run 状态 / 会话元数据
corepack pnpm bdd agent status --conversation-id <id> --run-id <runId>
corepack pnpm bdd agent inspect --conversation-id <id>

# 在下一个模型边界改口
corepack pnpm bdd agent steer --conversation-id <id> --run-id <runId> --idempotency-key k1

# 排队追加输入 / 取消 / 替换
corepack pnpm bdd agent follow-up --conversation-id <id> --run-id <runId> --idempotency-key k2
corepack pnpm bdd agent cancel    --conversation-id <id> --run-id <runId>
corepack pnpm bdd agent replace   --conversation-id <id> --run-id <runId> --idempotency-key k3
```

> 所有控制类命令都带 `--idempotency-key`，重试安全。

## 5. 与外部 Agent / IDE 集成

### 5.1 MCP stdio server（推荐）

```powershell
corepack pnpm bdd coding-run mcp
```

它把开发运行时以 MCP 工具形式暴露出来，外部 MCP 客户端（Claude Code、Codex、各类 IDE 插件等）可以：

| MCP 工具 | 作用 |
|---|---|
| `star_sanctuary_capabilities` | 查询当前运行时可用的能力 |
| `star_sanctuary_run_start` | 启动一次开发运行 |
| `star_sanctuary_run_subscribe` | 订阅运行事件流 |
| `star_sanctuary_permission_respond` | 回应权限请求（`allow` / `deny`） |
| `star_sanctuary_run_steer` | 中途改口 |
| `star_sanctuary_run_cancel` | 取消运行 |
| `star_sanctuary_run_artifact` | 读取运行产物 |

服务端声明的操作集合：`start / subscribe / permission.respond / conversation.steer / cancel / artifact.read`，权威执行方始终是 Gateway（`authoritativeOwner: gateway`）。

### 5.2 NDJSON 桥（自研客户端 / CI）

```powershell
corepack pnpm bdd coding-run stdio
```

- 协议版本 `v1`，每行一个 JSON 帧；
- 帧类型：`control.request/response`、`subscription.request/response`、`conversation.request/response`、`artifact.request/response`、`projection.request/response`，异常时回 `protocol.error`；
- 每个请求带 `id`，响应按 `id` 配对；订阅会持续推送事件。

### 5.3 桥接目标配置

```powershell
corepack pnpm bdd configure bridge --help          # 查看全部桥接模板
corepack pnpm bdd configure bridge codex-exec-mcp --workspace-root E:\project\star-sanctuary
corepack pnpm bdd configure bridge claude-code-exec-mcp --workspace-root E:\project\star-sanctuary
corepack pnpm bdd configure bridge starweaver-central --workspace-root E:\project\star-sanctuary --central-url <SSE URL>
```

细节见 `docs/cc与co桥接mcp配置与使用说明.md` 与 `docs/codebase-memory-mcp使用配置与限制说明.md`。

## 6. 会话取证与排障

```powershell
corepack pnpm bdd conversation list                       # 有哪些会话
corepack pnpm bdd conversation timeline --conversation-id <id> --preview-chars 200
corepack pnpm bdd conversation export   --conversation-id <id> --output-dir .\tmp\exports
corepack pnpm bdd conversation prompt-snapshot --conversation-id <id> --output-dir .\tmp\snapshots
corepack pnpm bdd console --watch --interval 5            # 运行态持续观察
corepack pnpm bdd doctor --check-model                    # 模型连通性
```

推荐排查顺序：

1. `bdd status` → Gateway 是否在跑；
2. `bdd doctor` / `bdd doctor --check-model` → 配置与模型连通；
3. `bdd conversation timeline` → 这一步到底发生了什么；
4. `bdd conversation prompt-snapshot` → 模型实际看到的 prompt 是什么；
5. `bdd console --watch` → 运行态资源与任务水位；
6. 日志：`<stateDir>/logs/`（daemon 模式为 `gateway.log`）。

## 7. WebChat 与 CLI 的差异（"变化在哪"）

| 维度 | WebChat（原有） | CLI / TUI / 无头（新增） |
|---|---|---|
| 入口 | 浏览器 `http://127.0.0.1:28889` | 终端 `bdd tui` / `bdd agent run` / 桥接 |
| 适用场景 | 聊天、语音、看板式治理 | 真实开发、自动化、被其他工具调用 |
| 变更查看 | 页面里的工具结果与详情 | `changes` 标签：工作区 + 检查点 + 逐 hunk |
| 权限确认 | 页面弹窗 | TUI 权限弹窗 / 无头 `--permission-mode` + 程序化 `permission_respond` |
| 成本护栏 | WebChat 成本预算提示 | `--max-cost-usd` / `--max-tokens` / `--max-turns` 硬停 |
| 自动化 | 需人工操作页面 | JSONL 事件、退出码、幂等控制命令、CI 可直接调 |
| 外部集成 | 无 | MCP stdio server（7 个工具）+ NDJSON v1 协议 |
| 取证 | 页面历史 | `conversation timeline / export / prompt-snapshot` |
| 运行态 | Doctor / 观测页面 | `bdd console --watch`、`runtime` 标签 |

**核心变化**：安全边界、状态目录、模型与工具治理完全共用；区别只在"操作界面"和"是否可被程序调用"。也就是说，你在 CLI 里做的事和 WebChat 里做的事，落到同一套 Gateway 执行、同一套 fail-closed 规则、同一份会话记录。

## 8. 从 WebChat 迁移到 CLI 的对照操作清单

> 先说结论：**不是所有 WebChat 功能都有等价 CLI 命令**。治理类页面（记忆、经验能力、长期任务、画布）目前只有 WebChat 与 RPC 入口。下表用三种标记：
> ✅ = 有等价 CLI 命令；🔁 = 可在 TUI / 无头运行里让 Agent 代劳；🖥️ = 暂无 CLI 入口，继续用 WebChat。

### 8.1 日常对话与开发

| WebChat 操作 | CLI 等价操作 | 说明 |
|---|---|---|
| ✅ 打开页面发消息 | `bdd tui` → `chat` 标签输入后回车 | 需先 `bdd start`；流式回复与工具摘要都在同一屏 |
| ✅ 允许 / 拒绝高风险工具 | TUI 权限弹窗（`↑↓` 选择请求、`Tab/←→` 切换选项、`Enter` 确认）；或运行前用 `--permission-mode` 定档 | 无头运行用 `bdd agent run --permission-mode plan\|accept-edits\|confirm` |
| ✅ 新建会话开聊 | TUI 里直接开聊；脚本化用 `bdd agent run`（不带 `--conversation-id` 即新会话） | |
| ✅ 继续历史会话 | TUI `sessions` 标签选中；或 `bdd agent continue --conversation-id <id>` | |
| 🔁 上传附件 / 图片 | 在 TUI 里给出文件绝对路径，让 Agent 用 `file_read` 读取 | CLI 无拖拽上传；需要多模态看图仍建议 WebChat |
| 🖥️ 语音输入 / 语音播报 | 仅 WebChat（`voice` / `natural-voice-*`） | CLI 无语音通道 |

### 8.2 变更查看与交付

| WebChat 操作 | CLI 等价操作 | 说明 |
|---|---|---|
| ✅ 看这次改了哪些文件 | `bdd tui` → `changes` 标签 → Revision Checkpoints | 显示 tracked / untracked / conflict 与变更路径 |
| ✅ 逐个改动细看 | `changes` 标签内 `PageUp` / `PageDown` 逐 hunk 浏览 | |
| ✅ 选择工作区 / 工作树 | `changes` 标签 → Worktrees 焦点 → `Enter` | 显示 ready / blocked / unavailable |
| ✅ 推送到远端仓库 | `changes` 标签内 `Ctrl+P` | 需 `BELLDANDY_REMOTE_DELIVERY_TARGETS_JSON` allowlist；未配置则无反应 |
| ✅ 预览某个检查点 | `changes` 标签 → Revision Checkpoints 焦点 → `Enter` | |

### 8.3 设置与接入

| WebChat 操作 | CLI 等价操作 | 说明 |
|---|---|---|
| ✅ 改模型 / API Key | `bdd config set BELLDANDY_OPENAI_MODEL <值>`（同理 `_BASE_URL` / `_API_KEY`）；或 `bdd config edit`、`bdd setup` | 改完需重启 Gateway |
| ✅ 看当前配置 | `bdd config list`（默认遮蔽敏感值，`--show-secrets` 才显示） / `bdd config get <KEY>` | |
| ✅ 确认配置文件位置 | `bdd config path` | |
| ✅ 迁移旧的 project-root env 文件 | `bdd config migrate-to-state-dir`（先加 `--dry-run` 预览） | |

| ✅ 配置定时任务 / 心跳 | `bdd configure cron` | 等价于 WebChat 的 assistant mode 开关收口 |

### 8.4 观测、排障与安全

| WebChat 操作 | CLI 等价操作 | 说明 |
|---|---|---|
| ✅ 系统检查 / Doctor | `bdd doctor`；`bdd doctor --check-model` 会真实发一次最小请求 | |
| ✅ 运行态与资源观测 | `bdd console [--json] [--watch] [--interval 5]` | 含 Gateway 连接/配对、体检计数、agents / subtasks、命令作业 |
| ✅ 启停与状态 | `bdd start [-d]` / `bdd stop` / `bdd status` | |
| ✅ 会话取证 | `bdd conversation list` / `timeline` / `export` / `exports` | |
| ✅ 看"模型到底看到了什么" | `bdd conversation prompt-snapshot --conversation-id <id>` | 等价于 WebChat 的 prompt 快照详情 |
| ✅ 配对管理 | `bdd pairing pending` / `approve` / `list` / `revoke` / `cleanup` / `export` / `import` | |
| ✅ 浏览器中继凭据 | `bdd relay start` / `bdd relay credential` | 凭据未配置时 Gateway 自动生成并落盘 |
| ✅ 成本护栏 | 无头运行 `--max-cost-usd` / `--max-tokens` / `--max-turns` 硬停 | 未配置模型定价时，带 `--max-cost-usd` 的调用会在请求前 fail-closed |
| 🖥️ 逐次 token / 成本账单面板 | 继续看 WebChat 的 token 用量观测 | `bdd console` 给的是运行态水位，不是逐次账单 |

### 8.5 暂无 CLI 入口（继续用 WebChat）

| WebChat 能力 | CLI 现状 |
|---|---|
| 🖥️ 记忆查看 / 检索 / 任务记忆 / 共享记忆审阅 / Dream | 面板仍只在 WebChat；CLI 里可 🔁 让 Agent 调用 `memory_search` 等工具 |
| 🖥️ 经验能力工作台（方法 / 技能候选、合成） | 面板仍只在 WebChat；CLI 里可 🔁 让 Agent 调用对应工具 |
| 🖥️ 长期任务（Goal）/ 子任务面板 | 面板仍只在 WebChat；CLI 侧可 `bdd agent task-projections` 读受限任务投影、`bdd console` 看统计 |
| 🖥️ 画布（Canvas）/ 计划面板 | 仍只在 WebChat |
| 🖥️ 摄像头 / 图片识别 / 视频理解面板 | 能力可通过工具触发，但配置与预览面板在 WebChat |

### 8.6 推荐迁移路线

1. **先自检**：`bdd doctor` → 确认状态目录、模型与配置都正常；
2. **切到终端做开发**：`bdd start` 后另开终端 `bdd tui --cwd <仓库>`，用 `chat` + `changes` + 权限弹窗完成一次真实改动；
3. **熟练后脚本化**：把重复动作写成 `bdd agent run`（带 `--permission-mode`、预算护栏、`--jsonl`），或接进 CI；
4. **需要被调用时**：`bdd coding-run mcp` 暴露给外部 Agent / IDE，或用 `bdd coding-run stdio` 走 NDJSON。

> 迁移期建议**双开**：WebChat 继续看记忆 / 经验 / 目标这些治理面板，TUI 负责改代码与交付。两者共用同一 Gateway 与状态目录，会话和配置是互通的，不需要二选一。

## 9. 配置与环境变量要点

### 9.1 三份模板的分工

| 文件 | 定位 |
|---|---|
| `.env.example` | 全量参考：所有变量 + 中文说明 + 默认值 |
| 状态目录 `.env.local` | **实际生效**的本地配置（Git 忽略） |
| `runtime.env.local`（发行模板） | 新用户开箱档：保留成熟默认与调优值，敏感值一律 `""` |

修改方式：`bdd config set <KEY> <VALUE>` 或直接编辑 `.env.local`，**重启 Gateway 生效**。

### 9.2 常用变量速查

| 变量 | 作用 |
|---|---|
| `BELLDANDY_STATE_DIR` | 状态目录（也是文件工具默认根） |
| `BELLDANDY_EXTRA_WORKSPACE_ROOTS` | 额外允许读写的根目录（逗号分隔） |
| `BELLDANDY_OPENAI_BASE_URL` / `_API_KEY` / `_MODEL` | 主模型接入 |
| `BELLDANDY_MODEL_CONTEXT_WINDOW` | 模型上下文窗口（影响压缩阈值推导） |
| `BELLDANDY_MODEL_INPUT_USD_PER_1M` / `_OUTPUT_USD_PER_1M` / `_CACHE_READ_USD_PER_1M` | 成本估算与 `maxCostUsd` 守卫的定价 |
| `BELLDANDY_MODEL_CACHE_ENABLED` | 声明模型支持 prompt cache（开启前缀稳定/缓存友好摘要） |
| `BELLDANDY_MODEL_JSON_RELIABILITY` | 工具参数 JSON 可靠性：`high` 不兜底 / `medium` 去重 / `low` 去重+修复 |
| `BELLDANDY_TOOL_AGENT_STREAMING_ENABLED` | 工具循环流式输出开关 |
| `BELLDANDY_DANGEROUS_TOOLS_ENABLED` | `run_command` 等危险工具总闸 |
| `BELLDANDY_COMMAND_SANDBOX_BACKEND` / `_OCI_RUNTIME` / `_OCI_IMAGE` | 命令 OCI 沙箱（未配置时命令执行 fail-closed） |
| `BELLDANDY_REMOTE_DELIVERY_TARGETS_JSON` | 受控远端推送 allowlist（TUI `Ctrl+P` 用） |
| `BELLDANDY_WORKFLOW_INLINE_ENABLED` / `_LEGACY_FILE_MODE` | 动态工作流脚本来源门控（默认关闭） |
| `BELLDANDY_BROWSER_RELAY_ENABLED` / `BELLDANDY_RELAY_TOKEN` | 浏览器中继开关与凭据（未设置时 Gateway 自动生成并落盘） |
| `BELLDANDY_WEB_FETCH_ALLOW_INSECURE_HTTP` / `_ALLOW_PRIVATE_NETWORK` | `web_fetch` 出站策略（默认全关） |
| `BRAVE_API_KEY` / `SERPAPI_API_KEY` | 内置 `web_search` 的搜索服务 Key（二选一；都不配则搜索不可用） |
| `BELLDANDY_WEBCHAT_COST_BUDGET_USD` / `_WARN_FRACTION` | WebChat 会话级成本预警 |

### 9.3 定价与汇率口径

- 变量单位是 **USD / 1M tokens**；人民币价 ÷ **7** 换算（2026-09 口径）。
- 发行模板按**高峰价**估算（高峰 = 空闲 × 2），避免低估支出。
- 例：空闲价 `0.02 / 1 / 4` 元（缓存命中 / 未命中 / 输出）→ 高峰 `0.04 / 2 / 8` 元 → 模板值 `0.00571429 / 0.28571429 / 1.14285714`。

## 11. 安全边界（务必了解）

- **默认 fail-closed**：能力缺失、预算超限、输出不符契约、沙箱不可用，一律停而不是降级。
- **权限三档**：`plan`（只读）/ `accept-edits`（允许改文件）/ `confirm`（每次确认）；无头运行请显式指定。
- **危险工具**：`run_command` 需 `BELLDANDY_DANGEROUS_TOOLS_ENABLED=true`；命令沙箱未配置时编码运行的命令执行会被拒绝。
- **远端推送**：只有 `BELLDANDY_REMOTE_DELIVERY_TARGETS_JSON` 里精确登记的 remote / 分支 / PR base 才能推送，不支持通配符。
- **出站策略**：`web_fetch`、浏览器工具默认禁止明文 HTTP 与私网访问，需显式开关。
- **敏感值**：`bdd config list` 默认遮蔽；日志与 WebChat 配置不回显凭据。

## 12. 常见问题

| 现象 | 原因 / 处理 |
|---|---|
| `bdd tui requires an interactive stdin and stdout` | 需要在真实交互终端运行（不要用管道 / CI） |
| `bdd agent run` 报 Gateway 不可用（退出码 7） | 先 `bdd start`，或 `bdd status` 确认 daemon |
| 无头运行因成本失败 | 未配置 `BELLDANDY_MODEL_INPUT/OUTPUT_USD_PER_1M` 时，带 `--max-cost-usd` 的调用会在 Provider 请求前 fail-closed；先配好定价 |
| 文件工具读写不到目标目录 | 文件工具默认以状态目录为根；其他盘符需 `BELLDANDY_EXTRA_WORKSPACE_ROOTS` |
| `web_search` 报"未配置" | 未设置 `BRAVE_API_KEY` / `SERPAPI_API_KEY`，二选一即可 |
| TUI 的 `Ctrl+P` 无反应 | 未配置 `BELLDANDY_REMOTE_DELIVERY_TARGETS_JSON`，或当前不在 changes 标签 |
| 改了 `.env.local` 没生效 | 需要重启 Gateway；`bdd config path` 可确认读的是哪个文件 |
| 模型名带 `expires-on-0910` 是否过期 | 不是过期，是**发行代号**（9 月 9 日灰度发行的 flash 新模型）；按新价配置即可 |
